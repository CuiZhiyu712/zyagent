# GGmall 电商订单与库存系统 README（脱敏演示版）

## 项目背景

GGmall 是一个模拟真实电商交易链路的 Java 后端项目，覆盖商品浏览、购物车、订单创建、库存扣减、支付回调、订单超时关闭和后台查询等核心流程。

项目目标是训练高并发场景下的库存一致性、缓存设计、事务控制和异步解耦能力。

## 技术栈

- Java 17
- Spring Boot 3
- MyBatis
- MySQL 8
- Redis
- RabbitMQ
- Docker Compose
- JUnit

## 核心模块

### 商品模块

- 商品列表分页查询
- 商品详情查询
- 商品上下架状态管理
- 热点商品 Redis 缓存

### 购物车模块

- 添加商品到购物车
- 修改商品数量
- 勾选商品

### 订单模块

- 创建订单

- 生成订单快照
- 支付成功后变更订单状态
- 超时未支付自动关闭

### 库存模块

- 库存预扣减
- 支付成功确认扣减
- 支付失败或超时释放库存
- 秒杀场景防止超卖

## 技术难点

### 防止库存超卖

问题：高并发下多个请求同时扣减库存，可能出现库存为负。

解决方案：

- 使用 Redis 分布式锁控制热点商品扣减入口。
- MySQL 更新库存时增加 `stock >= buy_count` 条件。
- 将库存变更记录写入库存流水，便于回滚和排查。

### 缓存一致性

问题：商品详情走 Redis 缓存，后台修改商品信息后可能出现脏读。

解决方案：

- 写操作先更新 MySQL，再删除 Redis 缓存。
- 对热点商品使用短 TTL，避免长期不一致。
- 缓存空值防止缓存穿透。

### 订单超时关闭

问题：用户下单后不支付，需要释放库存并关闭订单。

解决方案：

- 订单创建后发送延迟消息。
- 消费延迟消息时检查订单状态。
- 若订单仍为待支付，则关闭订单并释放库存。

### 慢 SQL 优化

问题：后台订单列表按用户、状态、时间筛选时响应较慢。

优化：

- 增加联合索引 `(user_id, order_status, created_at)`。
- 避免在 where 条件中对索引字段使用函数。
- 查询列表时只查必要字段，详情页再查完整快照。
